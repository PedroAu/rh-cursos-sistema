# Visual Regression Baseline — tests/baseline/

## Purpose

Este diretório contém screenshots de baseline para testes de regressão visual usando Playwright. Cada `.png` representa o estado esperado de uma página/componente em sua forma "correta".

## Why Are These PNGs Tracked in Git?

**Visual regression testing** exige comparação determinística entre o estado atual e o esperado. Manter os baselines no repositório garante que:

1. **Todos os developers têm a mesma referência** — não há ambiguidade sobre o que é o estado "correto"
2. **Histórico é rastreável** — mudanças no baseline são auditáveis via `git log`
3. **CI/CD é determinístico** — testes rodam contra o mesmo baseline em todos os ambientes
4. **PR reviews incluem diffs visuais** — revisor vê exatamente o que mudou na UI

## File Naming Convention

```
[page-name]-baseline-[viewport].png
```

Examples:
- `home-baseline-desktop.png` — Home page at 1280x720 (desktop)
- `home-baseline-mobile.png` — Home page at 375x667 (mobile)
- `blog-artigo-baseline-desktop.png` — Blog article at desktop resolution

## Updating Baselines

When the UI design **intentionally changes**, update baselines:

```bash
# Run Playwright in update mode
npx playwright test tests/visual.baseline.spec.ts --update

# Review the diffs (git diff tests/baseline/*.png)
git diff tests/baseline/

# Commit the updated baselines
git add tests/baseline/
git commit -m "test(visual): update baselines for [feature name]"
```

**Important:** Only update baselines for intentional design changes. If a test fails unexpectedly, investigate the regression first.

## File Size & Repository Growth

**Current state:**
- ~22 PNG files
- ~18 MB total (varies by complexity)
- Updated each time UI design changes

**Trade-offs:**
- ✅ Visual regression detection (deterministic)
- ✅ UI changes are git-auditable
- ❌ Repository grows with each baseline update
- ❌ Merge conflicts possible if multiple features touch same page

## Git LFS Evaluation

**Deferred:** Git LFS (Large File Storage) was evaluated but **not adopted** at this time.

**Rationale:**
- Adds infrastructure complexity (requires LFS server, CI setup)
- Team size doesn't require it yet (~22 baseline images)
- Current growth rate is manageable
- Risk of CI breakage if LFS misconfigured

**Recommendation:** Revisit if baselines grow beyond 100 files or >100 MB.

See `docs/architecture/TECHNICAL-DEBT-REPORT.md` for Git LFS as a future infrastructure improvement.

## Best Practices

1. **Keep baselines up-to-date** — stale baselines = false positives
2. **Don't commit snapshot-only changes** — update baselines in dedicated PR
3. **Review diffs carefully** — visual changes should be intentional
4. **Use mobile + desktop versions** — responsive design matters
