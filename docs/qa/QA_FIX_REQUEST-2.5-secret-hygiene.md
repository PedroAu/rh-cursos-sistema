## 🔴 FIX 1 — Hygiene check dá falso PASS (HIGH)

### Comportamento esperado
`npm run security:secrets` deve **falhar** quando existir qualquer `.env` gerado dentro de `.next/` ou `.open-next/`.

### Comportamento observado
`npm run security:secrets` **passou** mesmo com `.next/standalone/.env` presente no disco (verificado por execução nesta sessão, logo após um `build:cloudflare`).

### Causa raiz
`scripts/check-secret-hygiene.mjs:25-36` (`checkGeneratedEnvArtifacts`) usa:

```js
runGit(["status", "--ignored", "--short", ".next"]).filter((line) => line.endsWith("/.env"))
```

O git **colapsa** o diretório ignorado inteiro num único registro `!! .next/` — ele nunca lista o `.env` aninhado. Logo o filtro `endsWith("/.env")` retorna sempre vazio e o check é um no-op. Além disso, o script **nunca inspeciona `.open-next/`** (o artefato de deploy real).

### Como corrigir (recomendado: scan de filesystem)
Trocar a abordagem baseada em `git status` por uma varredura real de filesystem que cubra `.next` e `.open-next`:

```js
import { existsSync } from "node:fs";
import { execFileSync } from "node:child_process";

function findGeneratedEnvArtifacts() {
  const roots = [".next", ".open-next"].filter((dir) => existsSync(dir));
  if (roots.length === 0) return [];
  // -path '*/.env' casa qualquer .env aninhado; -type f evita falsos positivos
  const out = execFileSync(
    "find",
    [...roots, "-type", "f", "-path", "*/.env"],
    { encoding: "utf8" },
  );
  return out.split("\n").map((l) => l.trim()).filter(Boolean);
}

function checkGeneratedEnvArtifacts() {
  const artifacts = findGeneratedEnvArtifacts();
  if (artifacts.length > 0) {
    failures.push(
      "Generated env artifacts must be removed/excluded before packaging: " +
        artifacts.join(", "),
    );
  }
}
```

## 🔴 FIX 2 — Segredos no bundle de deploy (HIGH)

### Comportamento esperado
O bundle empacotado/deployado **não** deve conter `.env` com segredos.

### Comportamento observado
`.open-next/server-functions/default/.env` contém chaves de LLM do AIOX installer (DeepSeek/OpenRouter/Anthropic/OpenAI), copiadas do `.env` raiz (`mode 0600`, "Generated by AIOX Installer"). O Next standalone + OpenNext copiam `.env*` para a saída de build.

### Causa raiz
O `.env` raiz do app carrega segredos de **tooling do AIOX**, e o pipeline de build copia `.env*` para `.next/standalone/` e `.open-next/server-functions/default/`.

### Como corrigir (escolher 1, em ordem de preferência)
- **A (recomendado):** Tirar os segredos de tooling do AIOX do `.env` raiz do app. Mover as chaves de LLM para um local não copiado pelo build (ex.: `~/.aiox/.env` ou variáveis de shell). O `.env` raiz do app deve conter só o que o app precisa em dev.
- **B:** Adicionar um passo de build/deploy que remova `.env` do bundle antes do upload (ex.: `rm -f .open-next/server-functions/**/.env` no `predeploy`).
- **C:** Confirmar com @devops se `opennextjs-cloudflare deploy` realmente faz upload de `server-functions/**/.env` pro Worker. Se **não** subir, rebaixar a severidade; se subir, A ou B é obrigatório.

Documentar a mitigação escolhida em `docs/security/secret-hygiene-check.md` (a doc atual não menciona `.next`/`.open-next`).
