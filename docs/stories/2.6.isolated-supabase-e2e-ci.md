# Story 2.6: Isolate Supabase-backed E2E in CI

## Status

InProgress

## Context

The CI quality job exposed production Supabase and payment secrets to every
pull request while it did not run the Playwright suite. E2E must run only with
an explicitly declared Supabase test project and fail before browser startup
when the target is incomplete or points to production.

## Acceptance criteria

1. Standard lint, unit, and build checks run without production credentials.
2. Internal PRs and protected-branch pushes run Playwright with the `e2e`
   GitHub Environment.
3. Fork PRs never receive E2E credentials.
4. The E2E job fails closed if its project refs, URLs, credentials, or explicit
   write controls are invalid.
5. E2E executions against the shared test project are serialized.
