## Story

**As a** security-conscious maintainer,  
**I want** service-role Supabase usage audited and constrained to server-only boundaries,  
**so that** privileged database access cannot accidentally cross into client code or unsafe call paths.

## Acceptance Criteria

1. All `createAdminClient()` usages are inventoried with file path, purpose, and server-only justification.
2. Any client-boundary risk is either removed or documented as an explicit blocker with a follow-up story.
3. Server-only modules that use the service role are protected by existing framework conventions or explicit guards.
4. Tests or static checks cover at least the highest-risk boundary identified by the audit.
5. The audit result is documented in `docs/architecture/` or `docs/qa/` with clear allowed usage rules.
