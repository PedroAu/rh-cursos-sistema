## Story

**As an** operations/admin user,  
**I want** enrollment fallback behavior after RPC failure to be visible and verified,  
**so that** schema or RPC regressions do not silently create inconsistent enrollment side effects.

## Acceptance Criteria

1. The enrollment RPC path and direct fallback path are documented with their expected side effects.
2. Fallback execution produces an observable signal suitable for debugging without exposing sensitive applicant data.
3. Tests cover successful RPC, RPC failure with fallback success, and total failure behavior.
4. The fallback path is verified to write the same required business fields as the RPC path or the mismatch is documented as a blocker.
5. User-facing responses remain controlled and do not leak internal Supabase errors.
