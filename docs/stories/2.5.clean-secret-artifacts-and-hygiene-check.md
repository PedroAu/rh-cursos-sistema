## QA Results

### Review Date: 2026-06-21

### Reviewed By: Quinn (Test Architect)

### Verdict: FAIL

The story's two core deliverables — a working secret hygiene check (AC3) and ensuring generated secret artifacts are not packaged (AC2) — are not met. The hygiene script gives a **false PASS**, and real secrets are present in the actual deploy bundle. AC1 and AC4 are met.

> Note: all secret values below were masked during QA; no real secret was printed in logs, docs, or output.

#### Acceptance Criteria Traceability

| AC | Status | Evidence |
| --- | --- | --- |
| AC1 — `.env.example` sanitized | PASS | `check-secret-hygiene.mjs` `checkEnvExample()` enforces placeholder-only values for secret-named keys; `.env.example` is clean. |
| AC2 — generated `.next/standalone/.env` removed or excluded from packaging | **FAIL** | `.next/standalone/.env` regenerates on every build and is **not** excluded from packaging. The real deploy bundle `.open-next/server-functions/default/.env` contains AIOX-installer LLM keys (DeepSeek/OpenRouter/Anthropic/OpenAI), copied from the root `.env` ("Generated by AIOX Installer", mode 0600). Neither removal is durable nor is exclusion documented/enforced. |
| AC3 — hygiene check documented/scripted | **FAIL** | `scripts/check-secret-hygiene.mjs` exists, but `checkGeneratedEnvArtifacts()` is a no-op: `git status --ignored --short .next` collapses the ignored dir to a single `!! .next/` line, so the `.endsWith("/.env")` filter never matches the nested artifact. `npm run security:secrets` returns **PASS even while `.next/standalone/.env` exists** — false assurance. The check also never inspects `.open-next/` (the real deploy artifact). |
| AC4 — no `.env` secrets tracked in git | PASS | `git ls-files '.env*'` returns only `.env.example`; `.next` and `.open-next` are gitignored. No git-history leak. |

#### 7 Quality Checks

1. **Code review** — CONCERNS. The hygiene script's tracked-file and env.example checks are correct, but the generated-artifact check is logically broken (verified by execution).
2. **Unit tests** — CONCERNS. The hygiene script has no test; the broken branch would have been caught by a fixture asserting failure when a `.next/**/.env` exists.
3. **Acceptance criteria** — FAIL (AC2, AC3 not met).
4. **No regressions** — PASS (no app code touched).
5. **Performance** — N/A.
6. **Security** — FAIL. The control intended to prevent secret packaging does not work, and real LLM-provider secrets are present in the deploy bundle directory. Even though gitignored, they are bundled into the deploy artifact path.
7. **Documentation** — PASS (partial). `secret-hygiene-check.md` exists but does not address the `.open-next`/`.next` generated `.env` reality.

#### Required Fixes (to clear FAIL)

- **HYG-001 (HIGH):** Fix `checkGeneratedEnvArtifacts()` to actually detect nested env artifacts. `git status --ignored` collapses ignored dirs; use a real filesystem scan instead, e.g. find `.env` under `.next/` and `.open-next/` (`find .next .open-next -path '*/.env' -type f`), and fail if any exist. Add a unit test with a fixture that asserts the check FAILS when such a file is present.
- **HYG-002 (HIGH):** Prevent secrets from entering the deploy bundle. The root `.env` carries AIOX-installer LLM keys that Next standalone / OpenNext copy into `.open-next/server-functions/default/.env`. Options: (a) keep AIOX tooling secrets out of the app's root `.env` (move them to `~/.aiox` or a non-copied location); (b) strip `.env` from the bundle in the build/deploy step; (c) confirm with @devops whether `opennextjs-cloudflare deploy` actually uploads `server-functions/**/.env` and, if so, block it. Document the chosen mitigation in `secret-hygiene-check.md`.
- **HYG-003 (MEDIUM):** If any of the LLM keys in the root `.env` were ever shared/committed/bundled to a remote, rotate them (Dev Notes already mandate rotation on exposure).
