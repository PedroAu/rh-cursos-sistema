## Story

**As an** admin platform maintainer,  
**I want** every admin mutation to verify the current user is an admin inside the Server Action,  
**so that** privileged service-role operations cannot be invoked outside the authorized admin context.

## Acceptance Criteria

1. A shared server-only guard exists and verifies the current Supabase session plus `profiles.role === "admin"`.
2. Every exported mutation in `src/app/actions/admin.ts` calls the guard before privileged service-role writes or reads.
3. Unauthorized and non-admin callers receive a safe failure or no-op without mutating Supabase.
4. Tests cover at least one create, one update, one delete/soft-delete, and one settings/asset mutation path with unauthorized access.
5. The guard itself has tests for no user, non-admin user, and admin user.
6. Existing admin happy paths and validation errors remain unchanged.
