### Migration Pattern (Phase 3 example)

```tsx
// Before (inline Field wrapper)
<Field label="Name" name="name" />

// After (TextField variant)
<TextField
  label="Name"
  name="name"
  description="Full name as it appears in ID"
  required
/>
```

Error handling via Zod in server actions:
```tsx
const result = schema.safeParse(formData);
if (!result.success) {
  return { fieldErrors: flatten-zod-errors(result.error.flatten()) };
}
```

### Accessibility Improvements

- ✅ All fields render `aria-describedby` linking to help text.
- ✅ Error messages render with `role="alert"` (auto aria-live='assertive').
- ✅ Required indicators via hidden text + `<span aria-hidden>*</span>`.
- ✅ Checkbox Radix modeled as `z.literal('on').optional()` (handles Radix string output).

### Deviation from Initial Plan

**Expected:** Re-export logic in `shadcn/admin/form-field.tsx` for backward compat (Phase 1).

**Actual:** File removed entirely. Forms migrate directly to new system. No need for re-export—simpler, fewer moving parts.

**Why:** Direct imports are clearer, faster to audit, and avoid the "redundant file" pattern. All 12 forms already migrated, zero blocker.
