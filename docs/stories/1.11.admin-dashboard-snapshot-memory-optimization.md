## Story

**As an** admin user of rhcursos.com.br,
**I want** the admin dashboard (`/admin`) to load without the Cloudflare Worker hitting `Error 1102 (Worker exceeded resource limits)`,
**so that** the protected admin area is reliably available in production.

## Acceptance Criteria

1. `getAdminDashboardSnapshot()` no longer loads heavy `curso` text columns (`descricao`, `ementa`, `objetivos`, `beneficios`, `publico_alvo`) that the dashboard does not render.
2. `curso` and `turma` tables are loaded at most once each per dashboard request (no redundant loads across `getAdminCourses` + `getAdminAgenda`).
3. The `AdminDashboardSnapshot` output shape and every field consumed by `src/app/(admin)/admin/page.tsx` are preserved (metric cards, recent courses table, recent activities).
4. Lead data loaded for the snapshot is limited to the columns the snapshot consumes (no long free-text fields like `mensagem`, `objetivo_treinamento`, `desafios_principais`).
5. The other exported `admin-data` helpers (`getAdminCourses`, `getAdminLeads`, `getAdminAgenda`, etc.) remain unchanged so non-dashboard pages keep their current behavior.
6. Quality gates run: `npm run lint`, `npm run typecheck`, `npm test`, `npm run build:cloudflare`; results documented.

## Dev Notes

### Diagnosis Context (from Architect read-only analysis)

- Error 1102 = Worker exceeded resource limits. Admin CRUD components are `"use client"`, so heavy table render happens in the browser, not the Worker — CPU stays low (observed 119–409 ms CPU returning `ok` in `wrangler tail`). The hard, non-configurable **128 MB memory** limit is the pressured resource. Intermittency matches memory pressure (cold start + data volume).
- Highest memory consumer: `/admin` dashboard — `getAdminDashboardSnapshot()` ran a `Promise.all` of 7 operations, holding simultaneously: 200 full leads, all turmas, and all courses **with heavy text columns**, loading `curso`/`turma` 2–3× redundantly.

### Constraints

- Do not change `AdminDashboardSnapshot` consumers' expected fields.
- Do not push or deploy; `@devops` owns remote operations.
