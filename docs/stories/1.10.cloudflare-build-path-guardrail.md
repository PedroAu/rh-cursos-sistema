## Story

**As a** developer preparing deploys,  
**I want** project scripts and documentation to make the Cloudflare/OpenNext build path explicit,  
**so that** nobody treats plain `next build` or static Cloudflare Pages export as the production artifact.

## Acceptance Criteria

1. Existing build/deploy scripts are reviewed for ambiguity around production deploy artifacts.
2. Documentation clearly states that Cloudflare deployment uses OpenNext Workers.
3. `npm run deploy:check` or equivalent validation remains the recommended pre-deploy command.
4. Any script or doc wording that implies Vercel/static export production deploy is corrected.
5. The change does not alter runtime deployment configuration unless a concrete mismatch is found.
6. Validation commands run or skipped commands are documented with reasons.

### Architecture Context

- The app is deployed to Cloudflare Workers via OpenNext, not static Cloudflare Pages export or Vercel. [Source: `docs/architecture/system-architecture.md#Current Technical Debt and Known Issues`]
- `package.json` defines `build` (`next build`, framework-level build only) and `build:cloudflare` (`opennextjs-cloudflare build`, the actual production artifact) as separate scripts; the distinction must stay unambiguous in docs and script wording. [Source: `package.json`]
- `deploy:check` chains `lint && typecheck && test && build:cloudflare` and is the recommended pre-deploy validation command. [Source: `package.json`]
- `docs/deploy.md` already documents the deploy flow; verify it does not imply Vercel or static export as the production target. [Source: `docs/deploy.md`]
- `open-next.config.ts` and `wrangler.jsonc` define the actual Cloudflare Workers runtime configuration; this story should not change them unless a concrete mismatch with documentation is found. [Source: `open-next.config.ts`, `wrangler.jsonc`]
